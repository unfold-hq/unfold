# Troubleshoot CI and releases

Symptoms seen in Unfold's CI and releases, what caused them and what fixed them. [CI and release workflows](ci.md) explains how the pipeline is meant to work. The run and pull request numbers in the table refer to the archived Forgejo repository, where CI ran before [ADR-0055](../adr/adr-0055-github-unfold-hq-is-the-project-home.md).

## Read a run

Every run and log on `unfold-hq/unfold` is public: `gh run list --repo unfold-hq/unfold --workflow on_release_train.yml`, then `gh run view <run> --log-failed`. A rerun needs write access.

## Symptoms

| Symptom | Cause | Fix |
| --- | --- | --- |
| Every job of every workflow is skipped | The run is not in `unfold-hq/unfold`: a fork or a mirror. Each job's condition starts with the repository check. | Expected. Run it in `unfold-hq/unfold`. |
| A release tag exists but no **[Workflow] On Release Published** run started | A tag or release made with `GITHUB_TOKEN` starts no workflow, and the dispatch step after semantic-release failed or did not run. | Dispatch it at the tag: `gh workflow run on_release_published.yml --repo unfold-hq/unfold --ref <tag> -f tag=<tag>`. |
| `parse-release-tag` fails with "Select the same tag as the workflow ref" | The publication was dispatched on a branch. A branch run would sign under a branch identity the cluster refuses. | Dispatch it with `--ref <tag>`. |
| `build-contexts` fails in a CVE budget step | The image built, but Grype found a critical or high finding over the budget in [`apps/unfold/ops/security/cve-budgets.yaml`](../../apps/unfold/ops/security/cve-budgets.yaml). The job summary names the package. | Rerun once Wolfi ships the fix (the build takes the newest package), or move the base digest. Add a reviewed statement to [`apps/unfold/ops/vex/statements`](../../apps/unfold/ops/vex/README.md) only when the code is unreachable; never raise the budget. |
| The distribute job fails its anonymous pull with HTTP 401 | A new GHCR package starts private. | Make the package public in its settings, then rerun only the distribute job. |
| Open VSX refuses `--trusted-publishing` | `ovsx` is older than 1.4.0, the extension does not exist yet on Open VSX, or Trusted Publishing is not set up for this repository and workflow. | Move `ovsx` forward, publish the first `unfold-hq.unfold` with a token, or fix the publisher's Trusted Publishing settings. |
| The extension job fails with "already published without" an asset | The release was published before its assets were attached; GitHub keeps a published release immutable. | Never publish an Unfold release by hand; the distribute job does it. Delete the release and its tag only if no artifact was published, otherwise release the next candidate. |
| `on_ploeg_pin.yml` fails with "Auto merge is not allowed" | Auto-merge is off in the repository settings. | Allow auto-merge, then rerun the job. |
| A Ploeg pin merged, but no **[Workflow] On Source Change** run followed | A merge made with `GITHUB_TOKEN` starts no push run. | Expected: the next release train checks the head that holds it. |
| `release-policy` fails with `Cannot find module 'semantic-release'` | The job did not install the release toolchain before the tests. | Keep the `npm ci --prefix scripts/release-config` step before the release-policy action. |
| No new `unfold-v` tag for hours although application commits merged; **[Workflow] On Release Train** runs are green | Each train's `release` job printed `development moved past <commit>, the commit the checks passed`: merges kept landing during the train's checks. Or a train's `checks` or `ploeg-pin` failed, which shows red. | Wait for a quiet hour, or dispatch **[Workflow] On Release Train** on `development` after the last merge. Fix a red `checks` on `development` first; on 2026-10-24 run 2291 failed `docs.py --check` with `Stale landscape` after the rc.57 pin until #559 rebuilt the landscape. |
| `checks` runs for about 40 minutes; the summary shows groups `CANCELLED` and none `FAILED` | A gate in a later, unprinted group failed, and a cancelled gate never exited (run 538). | Fixed by [`scripts/verify-gate.mjs`](../../scripts/verify-gate.mjs): a cancelled gate is killed after a grace period and an orphaned process counts as a failure. |
| `fatal: tag '<x>' already exists` in `release` | Up to `unfold-v0.4.0-rc.114`, an orphaned release commit: the tag points at a release commit that is no longer on `development` (`git merge-base --is-ancestor <tag> origin/development` fails). Releases have committed nothing since the move to tags-only releases, so a new tag is always on the checked head of `development`. | Revert the duplicate release commit, then `git merge --no-ff` the orphan so the tag is reachable again. Never move a published tag. The release policy already refuses a version at or below any tag in the checkout, reachable or not. |
| Setup fails at `corepack pnpm install --frozen-lockfile` with `ERR_PNPM_FROZEN_LOCKFILE_WITH_OUTDATED_LOCKFILE` right after Renovate moved `packageManager` in `apps/site/package.json` or refreshed its lockfile (lock-file maintenance) | pnpm 11 and later record the pnpm that `packageManager` names in the lockfile's first document, `packageManagerDependencies`, and a frozen install refuses a record that disagrees. The self-hosted Renovate image runs its own global pnpm 10 (`binarySource=global`), which switches to the new pnpm with package-manager management turned off, so the rest of the lockfile moves and the record keeps the old version (pull request #593 on the previous forge, run 2423; reproduced byte for byte with Renovate's own lockfile step in `renovate/renovate:44.176.2-full`). | `renovate.json` runs `corepack pnpm install --lockfile-only --ignore-scripts --ignore-pnpmfile` in the package's directory after a pnpm update and after lock-file maintenance, which rewrites the record. Lock-file maintenance with the global pnpm drops the lockfile's first document entirely (#784 on the previous forge). A self-hosted Renovate runs it only once its `allowedCommands` lists `^corepack pnpm install --lockfile-only --ignore-scripts --ignore-pnpmfile$`; until then the pull request reports `has not been added to the allowed list`. By hand, run `corepack pnpm install --lockfile-only` in `apps/site` and commit the lockfile, as #596 did. |
| `ploeg-pin` or another short job hits its `timeout-minutes` while mise downloads Node, Go and Helm, although its `mise-action` sets `install_args: uv` | `mise exec -- <command>` installs every missing tool in `mise.toml` before it runs, so the job downloads the whole toolchain (release train run 2898, mise 2026.10.22). | Name the tool: `mise exec uv -- uv run …`. A job that installs one tool runs only that tool. |
| `checks` dies in under a minute with `<tool>@<version> is not in the lockfile` | A tool version in a `mise.toml` changed without `mise.lock`, and CI's install refuses a tool the lockfile does not hold. | Run `mise install` from the root and commit `mise.lock` with the change. |
| A `fix(ploeg)` pull request has a red `ploeg-docs` with `Stale decision register`, a stale combined glossary or `Stale landscape`; Renovate reports `Artifact file update failure` | The new Ploeg release adds an ADR or changes its domain model, and these pages are generated from the pinned contract bundle (run 1400, rc.16). On #369 on the previous forge, Renovate logged `Post-upgrade command './scripts/renovate-ploeg-docs.sh' has not been added to the allowed list in allowedCommands` and ran nothing. | Since [ADR-0041](../adr/adr-0041-a-ploeg-release-opens-unfolds-pin-pull-request-by-running-unfolds-recipe.md), Ploeg's release runs the script through `scripts/consume-ploeg-release.sh`. For the landscape, which needs a browser, and whenever the script could not regenerate a page, run `mise run domain`, `mise run docs-decisions` and `mise run landscape` on the branch and push. |
| A `build(ploeg)` pull request has a red `ploeg-docs` with `Combined glossary conflicts` and adds `ploeg-glossary-conflicts.txt`; Renovate may also report an artifact failure on older branches | The new Ploeg release defines a term Unfold's model also defines (rc.17: Tenant and Client). No regeneration can fix that. | Follow [the term clash steps](ci.md#the-ploeg-pin-pull-request) on the Renovate branch, as #339 on the previous forge did, then delete the report. |
| The nightly `ploeg-behind` job fails with `pins Ploeg <x>, but <y> is the newest release` | Ploeg published a release whose pin pull request has not merged: it is open and red, auto-merge was not turned on, or Ploeg's `consumers` job did not run (its `RELEASE_CONSUMERS` entry or the `unfold-hq-bot` App is missing, or the job failed). | Open the `ploeg/<y>` pull request and fix what holds it; rerun `on_ploeg_pin.yml` for it when auto-merge is off. When there is none, dispatch Ploeg's `Release consumers` workflow with `v<y>`, or run `scripts/consume-ploeg-release.sh <y>` on a branch and open the pull request by hand. |
| A unit test fails only in CI with a fixed short limit in its message, such as `opencode serve inside registry.example/agent:1.18.30 did not answer /global/health within 8s` (release train run 2399), or compares against a time taken when the module loaded (run 2362, fixed in #580 on the previous forge) | The test bounded real work (a fake engine, a relay, a spawned process, loopback HTTP) with a literal that fits an idle workstation. CI runners are short of CPU, so the work finishes, just later than the literal. | Bound waits with `scaledTimeout`, `deadlineAfter`, `waitFor` or `testTimeout` from `apps/unfold/test/timeframes.ts`; CI's verify action sets `UNFOLD_TEST_TIMEOUT_SCALE` to 2. A limit a test means to hit, against a fake that never answers, still fires, only later. Keep observation windows whose idle limit is fixed (the relay's idle-cut test) literal: a longer window there exposes more of the runner's pauses. `test/test-bounds.test.ts` fails on a test-level `timeout:` that is a literal. |
| A release hangs about 30 minutes, then `context deadline exceeded` | Something still addressed an old repository name: a redirect turned a POST into a GET, and a `git ls-remote` to a deleted repository waited for credentials (run 750 on the previous forge). | Use `unfold-hq/unfold` everywhere; the publisher sets `GIT_TERMINAL_PROMPT=0` and fails on a redirected write. |
